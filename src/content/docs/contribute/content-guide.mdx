## Where content lives

<FileTree>
- src/content/docs/
  - start-here/
  - learn/ one idea per page (type: concept)
  - cookbook/ playbooks and cookbooks (type: playbook | cookbook)
  - recipes/ one focused check or task (type: recipe)
  - showcase/ interactive labs (type: demo) and scenarios (type: showcase)
  - blog/ dated posts (type: blog)
- templates/ copy these to start a new page
</FileTree>

## Add a page

<Steps>
1. Copy the matching file from `templates/` into the right folder. The file name becomes the URL (`recipes/my-recipe.mdx` → `/recipes/my-recipe/`).
2. Fill in the frontmatter: `title`, `description`, `type`, `level`, `duration`, `tags`. Blog posts also need `date` and `author`.
3. Run `npm run dev` and check the page at `http://localhost:4321`.
4. Open a pull request. The page automatically appears in the sidebar, its section page, and the home page library.
</Steps>

## Frontmatter reference

| Field | Values | Purpose |
| --- | --- | --- |
| `type` | `concept`, `demo`, `cookbook`, `playbook`, `recipe`, `showcase`, `blog`, `guide` | Library tab and badge |
| `topic` | e.g. `Endpoint APIs`, `Kubernetes & NKP` | Library topic filter |
| `task` | e.g. `Connect & integrate`, `Benchmark & tune` | Library task filter |
| `sources` | list of `{ label, url }` | References at the end of the page |
| `cover` | image path, e.g. `../../../assets/showcase/x.jpg` | Card image in the Showcase view |
| `coverLabel` | short text | Text cover for scenarios without an image |
| `level` | `beginner`, `intermediate`, `advanced` | Badge and section filters |
| `duration` | e.g. `15 min` | Time estimate badge |
| `tags` | list of strings | Future search and topic pages |
| `sidebar.order` | number | Order in the sidebar and index |
| `draft` | `true` | Hides the page from production builds |

## Style checklist

- Lead with **what the reader will have** when they finish.
- List prerequisites before step 1.
- Use the `NAI_BASE_URL`, `NAI_API_KEY`, `NAI_MODEL` variables in all code.
- Put product-version-specific details in an `<Aside>` and name the release.
- Link the Nutanix documentation you relied on in `sources`.
- Interactive labs: add a kind to `src/components/LabDemo.astro`.
- Diagrams: use the `<Mermaid>` component.
