## What you'll build

A running endpoint serving an open model (for example a small Llama or Mistral instruct model), and a successful API call to it from your terminal.

## Prerequisites

- Access to a Nutanix Enterprise AI dashboard ([install guide](/tutorials/install-nai-on-kubernetes/))
- A Hugging Face access token, if the model you choose is gated
- At least one free GPU with enough memory for your model (see [AI inference basics](/concepts/ai-inference-basics/#why-gpus))

## Steps

<Steps>
1. **Import a model.** In the dashboard, open **Models** and import from the catalog. Start with a small instruct model (7–8B parameters) so it fits on a single GPU. Wait for the download to finish.

2. **Create an endpoint.** Open **Endpoints → Create**. Give it a short, memorable name (this becomes your `model` value), select the model you imported, and pick a GPU profile. Start with one replica.

3. **Wait until it's ready.** The endpoint status changes to *Active* once the model is loaded onto the GPU. Large models can take several minutes.

4. **Create an API key.** Open **API Keys → Create**, scope it to your endpoint, and copy it somewhere safe. You will not see it again.

5. **Call the endpoint.** Copy the base URL from the endpoint details page, then:

   ```bash
   export NAI_BASE_URL="<base-url-from-endpoint-page>"
   export NAI_API_KEY="<your-api-key>"
   export NAI_MODEL="<your-endpoint-name>"

   curl "$NAI_BASE_URL/chat/completions" \
     -H "Authorization: Bearer $NAI_API_KEY" \
     -H "Content-Type: application/json" \
     -d "{\"model\": \"$NAI_MODEL\", \"messages\": [{\"role\": \"user\", \"content\": \"Say hello from my private AI!\"}]}"
   ```
</Steps>

<Aside type="tip">
  Getting a TLS error in a lab? Your dashboard may use a self-signed certificate. Add your CA to your trust store rather than disabling verification.
</Aside>

## Check your work

You should get a JSON response with a `choices[0].message.content` field containing the model's reply.
