Place a semantic router ahead of approved inference endpoints. Use a labeled prompt set to evaluate model selection, fallback, and policy checks before enabling routing for live traffic.

## 01 · Define the routes

Create a small route table for coding assistance, internal policy questions, and general requests. Map each route to an approved model or application endpoint. Define where sensitive data may go before classification, including where the classifier runs.

## 02 · Configure confidence and fallback

Use a labeled validation set to pick a threshold. Send uncertain prompts to a policy-approved default or ask for clarification. Keep the route allowlist independent of classifier output.

## 03 · Run in shadow mode

Record predicted routes without changing live destinations. Compare route decisions with human labels, including ambiguous prompts, mixed intent, and requests that try to override policy.

## 04 · Measure the rollout

Check per-route quality, misroute rate, fallback frequency, router latency, and end-to-end latency. If eligible replicas exist behind a route, apply KV-aware selection within that pool.
